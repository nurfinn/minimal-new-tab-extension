# Повторная оценка UI/UX — 30 сентября 2026

## Задача и границы проверки

Пересмотреть проблемы без опоры на прежние выводы и подготовить план, а не менять продукт. Основание: предоставленные пользователем скриншоты Chrome/Firefox, текущий исходный код и новый запуск изолированных Chromium/Firefox с тестовыми данными. Пользовательские профили, настройки, установленные расширения и магазинные ZIP не изменялись.

Это целевая повторная проверка настроек, формы сайта и навигации по папкам, не заявление о полном аудите доступности или всех сценариев приложения.

### Почему расходится статус иконок

`firefox/firefox-bootstrap.mjs` сначала запускает `initializeFaviconSettings()`. Модуль правильно выставляет статус по разрешению. Затем импортируется `newtab.js`, вызывающий `localizeDocument()`. У динамических mode/status в HTML остались статические `data-i18n` для выключенного режима: локализация перезаписывает корректный текст.

Воспроизведение подтверждает отдельный дефект текущего исходного кода. Ответ пользователя «при повторном открытии исчезает» не полностью совпал с тестом: в изолированном запуске стартовое противоречие оставалось и после закрытия/открытия.

**Уточнение после нового скриншота пользователя:** в его показанном эпизоде Firefox ещё ждёт ответа в системном окне согласия. Для этого эпизода «Выключено» соответствует ещё не включённой загрузке, а положение переключателя меняется преждевременно. Нельзя объяснять данный скриншот перезаписью перевода: эта ошибка выявлена отдельно и сохраняется в плане как самостоятельный regression case. При включении статус должен быть «Ожидает разрешения» / Waiting for permission, переключатель — временно недоступен и в последнем подтверждённом положении; после Allow — On, после Deny — Off. Формулировки системного окна принадлежат Firefox, не интерфейсу расширения.

## Проверенные шаги

1. Открытие Background в Chrome EN — основные действия доступны, но управление фоном раздроблено.
2. Раскрытие Site icons в Firefox RU — воспроизведены неверные подписи и нехватка высоты для всего содержимого.
3. Прокрутка раскрытых настроек Firefox при 1024×600 — Save достижим, заголовок и Close теряются.
4. Открытие Add site — сохранён удачный URL с иконкой/карандашом; native стрелка выбора папки близка к краю.
5. Переход на Import/export — блок иконок Firefox остаётся над вкладками, хотя не относится к переносу данных.
6. Запрос разрешения с задержкой и отказ — ожидание не обозначено, после отказа переключатель возвращается в правильное положение.

Ошибок выполнения JavaScript в этих ограниченных сценариях не получено. Полный тестовый набор в рамках этой проверки не запускался.

## Рекомендуемое направление

- Сохранить две вкладки, но первая должна честно называться «Основные» / General: она содержит фон и другие предпочтения. Вторая — «Импорт и экспорт» / Import and export.
- В General: один блок фона с preview, сменой и возвратом к стандартному; компактная группа подложки; отдельная группа управления. Иконки Firefox находятся здесь, а не выше обеих вкладок.
- Не прятать один переключатель Firefox за отдельной рекламной полосой из пяти логотипов и кнопкой Configure. Короткая строка настройки + краткое объяснение приватности; детали можно раскрыть отдельно.
- Save/Cancel относятся к черновику фона и горячих клавиш. Возврат стандартного фона меняет черновик, а не неожиданно закрывает окно. Разрешение Firefox запрашивается прямым действием пользователя и явно применяется сразу; Cancel его не отменяет.
- Header/Close и footer остаются на месте, прокручивается одна центральная область. В Data вместо Save показываются только относящиеся к импорту/экспорту действия.
- Сохранить текущие карточки, blur, положение и высоту навигации, иконки верхних кнопок, одобренный URL + favicon/pencil, emoji и свайпы.

Это направление для следующих макетов, не уже утверждённый финальный дизайн.

## Ограничения

- Новые browser captures сделаны в headless Chromium/Firefox поверх localhost; API хранилища и разрешений заменены тестовыми реализациями. Оригинальный application/build code не менялся.
- Не проверены настоящее системное окно согласия Firefox, личные настройки масштаба и межустройственная синхронизация. Различия native controls и GPU/blur в headless не считаются доказательством их вида в пользовательском браузере.
- Контраст, видимость фокуса и размер целей требуют проверки финальных вариантов на разных фонах; полная доступность по скриншоту не подтверждается.
