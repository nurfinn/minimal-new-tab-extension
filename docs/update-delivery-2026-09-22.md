## 1. Что отвечает сервер Google

Проверен официальный endpoint Chrome Web Store `https://clients2.google.com/service/update2/crx` для расширения `leofpnfpnigcbglbpknooldoaflbokcj`. Этот адрес указан в [документации Chrome](https://developer.chrome.com/docs/extensions/how-to/distribute/install-extensions).

Контрольные GET-запросы были сделаны напрямую, без авторизации в аккаунте пользователя и без запуска его браузера. Параметры: `response=updatecheck`, `prodversion=146.0.0.0`, `acceptformat=crx3`, `x=id=<extension-id>&v=<extension-version>&uc`. Версия браузера здесь — параметр диагностического запроса, не измеренная версия устройства пользователя.

| Переданная версия расширения | HTTP | Ответ сервера |
| --- | --- | --- |
| 1.5.4 | 200 | `status="ok"`, предлагается версия 1.6 и URL CRX |
| 1.5.5 | 200 | `status="ok"`, предлагается тот же пакет 1.6 |
| 1.6 | 200 | `status="noupdate"` |

**Вывод:** 1.6 доступна не только как новая установка: сервер предлагает её и в ответ на запрос обновления старых версий с этими параметрами. Это не доказывает 100-процентное распространение для всех групп пользователей, успешное скачивание на их устройствах или применение обновления конкретным браузером.

CRX, на который сослался сервер обновлений, скачан в память и разобран без установки или исполнения его кода. Завершающая проверка прошла 2026-09-22 в 10:36:58 UTC (14:36:58 Asia/Dubai).

- Разрешения: только `storage` и `favicon`.
- `minimum_chrome_version` и background/service worker отсутствуют.
- `update_url` в опубликованном пакете: стандартный адрес Chrome Web Store.
- Размер CRX: **673 725 байт**.
- SHA-256 CRX совпал с хешем из ответа сервера: `6311dc9652126e5e4f927fa5ce49ff63aba28d86ad01717c864b4af6a60bddb0`.
- Проверенный локальный ZIP: `../minimal-new-tab-chrome-v1.6.zip`; SHA-256: `370b139877761ebe180d7d923ab4381f087a8ef094aebbc4e8b42ea5ee537794`.
- Все **16 файлов**, кроме manifest, из локального ZIP совпали с магазинным пакетом побайтно. Единственное отличие manifest — присутствующий в магазинном CRX `update_url`. Единственный дополнительный файл — `_metadata/verified_contents.json`.

Сверка не является отдельной проверкой криптографической подписи CRX: проверялись скачивание по HTTPS, хеш из update-ответа, содержимое ZIP и соответствие локальному релизу.

В первом прогоне диагностическая проверка ошибочно ожидала ещё и добавленное магазином поле `key`. Фактически его нет. Проверено точное отличие (`update_url`); повторный прогон всех сравнений завершился успешно. Это исправление ожидания диагностического скрипта, не ошибка расширения и не изменение продукта.

**Вывод:** проверенный опубликованный пакет соответствует подготовленному Chrome-релизу 1.6. Признаков загрузки чужого/старого кода под новым номером или неверного адреса обновлений не обнаружено.

## 3. Что проверено в исходниках

Сравнение `manifest.json` версии 1.5.4 (коммит `e00d3e3`) с текущими исходниками показало только изменение `version` на `1.6`. Новых разрешений и нового ограничения минимальной версии Chrome нет.

В текущем коде нет обработчиков `onUpdateAvailable`, вызовов `requestUpdateCheck` или `runtime.reload`, которые управляли бы применением обновления. Следовательно, гипотеза о задержке из-за добавленного нами обработчика к текущей версии не относится.

Это сравнение исходников не заменяет проверку manifest и источника установки конкретного старого клиента.

## 8. Гипотезы и следующий шаг

Chrome может откладывать установку, пока открыты страницы расширения. Для Minimal Tab это остаётся правдоподобной гипотезой, но не доказательством причины массового отставания. [Жизненный цикл обновления Chrome](https://developer.chrome.com/docs/extensions/develop/concepts/extensions-update-lifecycle).

Свежая статистика подтверждает, что к 20 сентября большинство учтённых установок всё ещё оставалось на 1.5.4. Опубликованный пакет, показанные настройки кабинета и источник установки пользователя проверены. Для дальнейшей клиентской диагностики нужна реальная старая магазинная установка: в исследованном профиле её нет. Проверка локальной распакованной копии не заменяет проверку магазинной установки. Перезапуск, закрытие пользовательских вкладок, принудительное обновление или изменение настроек — отдельные действия, не подразумеваемые чтением.

Не переустанавливать расширение и не сбрасывать данные ради диагностики. Подготовлен [английский черновик обращения в поддержку Chrome Web Store](chrome-web-store-support-2026-09-22.md) с датами, ID и результатами проверок. Он сохранён только локально и не отправлен. Google отдельно относит проблемы статистики кабинета к вопросам для поддержки. [Каналы поддержки CWS](https://developer.chrome.com/docs/webstore/review-process#developer-communication).

После просьбы пользователя самостоятельно заполнить открытую вкладку 22 сентября выполнена попытка отправки через видимый интерфейс формы. Тема сокращена до лимита 100 символов. И категория `Other`, и категория `Item status` привели к шагу `Contact options` без способа связи: форма сообщила, что специалисты не смогут помочь по выбранным ответам. Поля подробного описания и вложений не появились, заявка не отправлена, номера обращения нет. Аккаунт формы совпадает с аккаунтом открытого кабинета издателя. Официальная ссылка One Stop Support с английским языком также перенаправляет на общий `gethelp`.

Вкладка поддержки оставлена открытой с заполненной краткой темой; подробный текст и скриншоты не отправлялись. Использовался интерфейс доступности macOS, а не JavaScript в странице; временное включение дерева доступности возвращено в исходное состояние.

После отдельного явного согласия пользователя 22 сентября в Chromium Extensions отправлен [публичный вопрос о доступном канале поддержки](chromium-support-access-2026-09-22.md). В него не включены скриншоты, ID расширения, числа из статистики или приватные данные профиля. Google Groups подтвердил: «Сообщение отправлено, но ожидает одобрения». Публичная видимость ещё не подтверждена; ссылка на отдельную тему и номер обращения не предоставлены. Это не заменяет приватную заявку с диагностикой. Для публикации потребовалось вступить в группу; общая рассылка группы отключена и настройка сохранена. Автоматическое наблюдение не создавалось.

Пока нет оснований менять разрешения, вручную добавлять `update_url` в исходный ZIP или выпускать новый пакет только ради предполагаемого исправления доставки. Уведомление остаётся отдельной задачей будущего релиза, не способом задним числом изменить установленную 1.5.4.

Для Firefox ранее выявлен отдельный риск: наличие обработчика `onUpdateAvailable` меняет момент применения обновления. Его нельзя добавлять механически под видом исправления Chrome. [Документация Mozilla](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/runtime/onUpdateAvailable).
