# Firefox v1.5.4 Build Design

## Goal

Produce one Firefox Add-ons-ready archive for Minimal New Tab v1.5.4 while leaving the existing Chrome v1.5.4 archive unchanged. The Firefox interface must use the same HTML, CSS, copy, layout, backgrounds, folders, sites, import/export, shortcuts, and interactions as the Chrome release.

## Release artifacts

- Keep `/Users/nurfinn/Documents/Codex/2026-06-28/new-chat/outputs/v1.5.4-store.zip` unchanged.
- Build an unpacked Firefox directory at `/Users/nurfinn/Documents/Codex/2026-06-28/new-chat/outputs/minimal-new-tab-extension-v1.5.4-firefox`.
- Build the AMO upload archive at `/Users/nurfinn/Documents/Codex/2026-06-28/new-chat/outputs/minimal-new-tab-firefox-v1.5.4.zip`.
- The ZIP root contains `manifest.json`; it does not wrap the extension in another directory.

## Architecture

The repository remains the single source of truth. A Firefox build script copies the release allowlist into a clean output directory, replaces the Chrome manifest with a Firefox-specific manifest, and overlays a tiny Firefox favicon provider. Shared application modules use a minimal browser API selector that prefers the Promise-based `browser` namespace in Firefox and falls back to `chrome` in Chromium.

The existing Chrome release ZIP is not rebuilt, edited, or replaced. Cross-browser source changes must preserve the current Chrome branch behavior and be covered by regression tests.

## Firefox manifest

The Firefox package uses Manifest V3 and includes:

- localized name, short name, and description;
- version `1.5.4`;
- the existing `chrome_url_overrides.newtab` entry;
- only the `storage` API permission;
- `browser_specific_settings.gecko.id` set to `minimal-new-tab@nurfinn.com`;
- `browser_specific_settings.gecko.strict_min_version` set to `140.0`;
- `browser_specific_settings.gecko.data_collection_permissions.required` set to `["none"]`;
- no `favicon`, identity, tabs, history, host, or optional host permissions.

The build targets Firefox Desktop only. It does not declare `gecko_android`.

## Favicons and privacy

Chrome keeps its existing favicon order in the default favicon provider: the Chrome `_favicon` endpoint, then the Google hostname service, then the visible letter fallback.

The Firefox build replaces that provider with a Firefox-only `buildFaviconSources()` implementation that always returns an empty list. The packaged Firefox source therefore contains neither the Google favicon URL nor the unsupported Chrome `_favicon` endpoint, and the existing letter fallback stays visible for every saved site. No favicon URL, image, or base64 data is persisted.

The extension has no backend, analytics, advertising, OAuth, or passive third-party network calls in Firefox. User-initiated navigation to saved links and the `nurfinn.com` product link remains normal browser navigation.

## Storage and migration

Firefox uses `browser.storage.sync` and `browser.storage.local` through the same storage service and schema already used by Chrome:

- lightweight application state is synchronized through the user's Firefox/Mozilla account;
- a custom background remains device-local;
- a missing local custom background safely falls back to the bundled default background;
- corrupted storage and read/write errors retain the existing safe fallback behavior;
- Chrome Sync data does not cross into Firefox automatically;
- the existing JSON import/export remains the supported Chrome-to-Firefox transfer path for sites, folders, their order, and the selected folder.

## UI behavior

The Firefox build copies the same `newtab.html`, `styles.css`, locale catalogs, icons, bundled background, and application logic. There are no Firefox-only layout, controls, copy, onboarding, consent dialog, or visual changes. The only intentional visible difference is the letter fallback in place of site favicons.

## Build and verification

Automated tests cover:

- the Firefox manifest contract;
- the Firefox release allowlist and clean output;
- Promise-based Firefox API selection without changing Chrome selection;
- the Firefox favicon provider returning an empty array and containing no remote service URL;
- unchanged Chrome favicon source order;
- preservation of identical UI assets in the Firefox output.

Final verification includes:

- the complete Node test suite;
- Mozilla `web-ext lint` with zero errors and zero warnings against the built Firefox directory;
- ZIP structure and checksum confirmation;
- a Firefox Desktop smoke test when a Firefox binary can be obtained in the environment, covering new-tab override, storage persistence, add/edit/delete/reorder, settings, import/export, default background, custom-background fallback, shortcuts, and absence of runtime exceptions.

If a Firefox browser binary cannot be run, this limitation is reported explicitly; it does not weaken the required automated tests or AMO validation.

## Store copy

The handoff includes concise Firefox Add-ons listing text in Russian and English. It explains the new-tab purpose, folders, backgrounds, shortcuts, Firefox Sync, import/export, device-local custom backgrounds, and the privacy-preserving letter icons without technical jargon.

## Out of scope

- Changing or rebuilding the Chrome release archive.
- A second codebase or manually maintained full Firefox copy.
- Firefox for Android.
- Remote favicon services or favicon consent UI.
- OAuth, backend, analytics, import/export format changes, new settings, or visual redesign.
