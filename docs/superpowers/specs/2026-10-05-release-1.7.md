# Release 1.7 — approved scope

The user accepted preparation of 1.7 for Chrome and Firefox: update versions and
README, build separate upload folders/ZIPs, verify those exact artifacts, then
commit/push and hand off files with the existing media and What's New.

## Constraints

- Both manifests and default JSON `appVersion` are `1.7`. Backup format stays v2;
  sync schema, extension IDs, permissions and all product behavior stay unchanged.
- Retain published 1.6 references where they describe compatibility, immutable
  fixtures or previous history. Published 1.6 and earlier cannot import JSON v2;
  this release still imports v1. Background images remain local, outside JSON.
- Keep wallpaper, approved icons, personal Chrome/Firefox installations, original
  media, published 1.6 ZIPs and existing main checkout unchanged.
- Produce new `minimal-new-tab-{chrome,firefox}-v1.7` folders and matching ZIPs in
  the existing outputs directory. Abort rather than overwrite a pre-existing 1.7
  artifact not created by this execution.
- README must distinguish prepared 1.7 from published 1.6. Add accurate release
  notes and What's New RU/EN for each browser, reusing the approved media copy.
- Validate unit/contracts, independently built browser QA packages, final ZIP
  entries/bytes, Firefox lint, localization, protected files and runtime deltas
  relative to accepted checkpoint `56b45c7`.
- Work on `codex/ui-polish-settings-toolbar-20260930`, push that branch only.
  No merge to main, PR, GitHub Release/tag, store submission or personal install.
  Enable the existing read-only validation workflow for pushes to `codex/**`.
- State real cross-device sync, signed store delivery and persistent signed
  Firefox restart limits honestly. Do not equate automated checks with these.

## Acceptance

Both upload packages have manifest 1.7, default exported metadata 1.7, unchanged
permissions/IDs and accepted runtime bytes except those two intentional metadata
deltas. Source/docs describe preparation without claiming publication. A clean
commit is pushed to the agreed remote branch, and ZIP/folder/media links are given.
