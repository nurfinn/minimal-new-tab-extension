# Firefox v1.5.5 Favicons Design

## Goal

Improve favicon coverage in the Firefox release without changing Chrome. Firefox v1.5.5 uses a curated local icon catalog first, an optional consent-based network fallback second, and the existing visible letter fallback last.

The feature is successful when common sites show recognizable icons without a network request, unknown sites always retain a clean letter fallback, and users can explicitly opt in to loading missing icons from the internet.

## Release isolation

- This is a Firefox-only v1.5.5 change.
- The Chrome manifest, source behavior, favicon order, release directory, and `/Users/nurfinn/Documents/Codex/2026-06-28/new-chat/outputs/v1.5.4-store.zip` remain unchanged.
- Firefox-specific UI, permissions, icon assets, and runtime behavior live under `firefox/` and are applied only by `scripts/build-firefox.mjs`.
- Shared files may be copied into the Firefox output, but the build must use narrow, test-anchored Firefox overlays or transformations. The source files used to build Chrome must not gain the Firefox setting or Firefox permission flow.
- The final artifact is a separate Firefox v1.5.5 archive with `manifest.json` at the ZIP root.

## Favicon resolution

Firefox resolves each site icon in this order:

1. A locally packaged icon matched by a deterministic service registry.
2. If the user has enabled remote loading and Firefox reports the required optional consent, `https://<hostname>/favicon.ico`.
3. If the direct icon is missing or unusable, the Google hostname favicon service with only the hostname and size.
4. The first letter of the site title, visible before any image loads and retained if every image source fails.

No broken-image indicator is visible at any stage. An image remains hidden until it has loaded and passed the existing minimum-size validation. Failed sources have their `src` removed before the letter fallback is restored.

The local resolver may inspect a normalized URL path only for a small set of trusted service rules, such as distinguishing Google Sheets, Docs, and Slides under `docs.google.com`. A remote request receives only the normalized hostname. Paths, queries, document IDs, account IDs, folder IDs, and saved site titles are never sent.

The resolver accepts normalized web URLs only. Invalid URLs, non-HTTP protocols, missing hosts, permission errors, network failures, redirects to unusable images, and tiny placeholder images all end at the letter fallback without throwing.

## Local icon catalog

The first Firefox v1.5.5 catalog contains at least the following service families and their common hostname aliases:

- Google: Search, Gmail, Drive, Docs, Sheets, Slides, Calendar, Meet, Maps, Photos, Translate, YouTube, Google Cloud, Analytics, Ads, Tag Manager, Search Console, and Looker Studio.
- AI: ChatGPT/OpenAI, Claude/Anthropic, Gemini, Perplexity, Grok, DeepSeek, Mistral, Hugging Face, Midjourney, Copilot, Poe, Cursor, and Replit.
- Social and communication: Reddit, Facebook, Instagram, X/Twitter, LinkedIn, TikTok, Pinterest, Discord, Telegram, WhatsApp, Slack, and Zoom.
- Development and cloud: GitHub, GitLab, Vercel, Railway, Netlify, Cloudflare, Namecheap, AWS, Azure, Docker, npm, Stack Overflow, Supabase, and Firebase.
- Productivity and design: Notion, Figma, Canva, Trello, Asana, Linear, Jira, Webflow, and Dropbox.

The catalog is a small, independently tested Firefox module rather than conditionals spread through rendering code. Exact host matches take precedence over parent-domain aliases, so `sheets.google.com` never falls through to the generic Google icon. Known aliases such as `twitter.com` and `x.com` point to the same local asset.

Icons are verified, lightweight packaged SVG or PNG assets with transparent backgrounds. They are not hotlinked and are not generated approximations of brand marks. Source and license provenance is recorded in a Firefox asset notice. The catalog can be extended in later Firefox releases without changing persisted site data.

## Settings UX: option C

The existing settings dialog keeps its two tabs, **Background** and **Import and export**. No third tab or sidebar is added.

A compact Firefox-only **Site icons** row appears below the dialog title and above the tabs. Its collapsed state contains:

- a small sample of local icons;
- the status **Local icons + letters** when remote loading is off;
- a quiet **Configure** button.

The button expands an in-place disclosure containing:

- the switch **Load missing site icons**;
- an explicit **Off** or **On** status;
- concise privacy text explaining that only the domain is sent and full links are not sent.

When enabled, the collapsed status changes to **Local + downloaded icons**. The Russian locale uses equivalent copy:

- **Иконки сайтов**
- **Локальные + буквы**
- **Настроить**
- **Загружать недостающие иконки**
- **Выключено / Включено**
- **Для загрузки передаётся только домен. Полная ссылка не отправляется.**

The disclosure follows the existing settings typography, spacing, radius, colors, focus treatment, and responsive modal width. It is keyboard accessible, exposes expanded state with `aria-expanded`, labels the switch, and does not change the Background or Import/export panels.

## Consent, privacy, and permission state

Remote favicon loading is off by default for new and upgrading users. Local icons and letters require no network access or consent.

The Firefox manifest declares:

- required data collection as `none`;
- optional `browsingActivity` data collection, because a domain identifies a visited or saved website;
- no `tabs`, `history`, `<all_urls>`, or broad host permission.

Turning the switch on calls `browser.permissions.request({ data_collection: ["browsingActivity"] })` directly inside the switch's user-activated event handler. Network favicon requests begin only after Firefox returns a grant. If the user declines, the control returns to off and the local/letter behavior continues unchanged.

Turning the switch off removes the optional consent and stops future remote requests. The UI also reads `browser.permissions.getAll()` when the page opens and reacts to permission changes made through `about:addons`. Firefox's permission state is the source of truth; the consent is not copied into `storage.sync`, because another device must make its own choice. On Firefox versions or environments where the built-in data-consent API is unavailable, remote loading remains off.

No favicon image, base64 data, blob, downloaded icon, favicon URL, request history, or analytics event is saved in `storage.sync`, `storage.local`, IndexedDB, or localStorage. Existing site URLs remain in the current application storage schema; that schema is not changed for this feature.

## Firefox-only component boundaries

- `firefox/favicon-catalog.mjs` owns service aliases and local URL/path matching.
- `firefox/favicon-service.mjs` owns source ordering, permission-aware remote source construction, and safe fallback inputs exposed to the existing renderer.
- `firefox/favicon-settings.mjs` owns the option C disclosure, permission request/removal, and live status.
- `firefox/favicon-settings.css` owns only the Firefox-specific settings row and disclosure styles.
- `firefox/site-icons/` contains the release icon assets and provenance notice.
- `scripts/build-firefox.mjs` copies the Firefox assets and applies the Firefox-only HTML/module/style hooks to the clean build output.

The application renderer continues to receive an ordinary ordered array of favicon sources and does not know about the local catalog, Firefox consent taxonomy, or provider details. Existing storage modules remain untouched.

After a permission change, visible cards refresh their favicon candidates without altering sites, folders, order, background, or settings data. The letter is rendered first and remains visible until an icon is confirmed usable.

## Error handling

- A rejected permission request leaves the switch off and does not show an error modal.
- A permission API exception leaves the switch off, retains local icons and letters, and may show a short inline status.
- Revoking consent in `about:addons` immediately disables remote sources for subsequent renders; the next new tab starts local-only.
- Offline mode, tracking protection, DNS failure, provider failure, CSP rejection, HTTP errors, invalid images, and tiny placeholders silently advance to the next source.
- If all sources fail, the favicon image has no `src` and the letter remains visible.
- A malformed catalog entry is ignored rather than breaking site rendering.

## Testing and release verification

Automated tests cover:

- exact-host, alias, and trusted Google path matching;
- representative entries from every catalog family;
- precedence of specific services over parent domains;
- invalid and non-web URLs;
- local-first ordering;
- no remote source when optional consent is absent;
- direct-host then hostname-service ordering when consent is present;
- proof that remote URLs contain no saved path, query, title, or identifier;
- permission request only from a user action;
- denied, unavailable, removed, and externally revoked permission states;
- letter-first rendering and absence of a broken-image state;
- option C markup, keyboard semantics, Russian and English localization;
- no favicon data or setting added to the persisted application schema;
- Firefox release allowlist, manifest contract, and packaged icon provenance;
- unchanged Chrome manifest, favicon provider behavior, UI contract, and existing Chrome archive checksum.

Final verification includes:

- the complete Node test suite;
- deterministic Firefox v1.5.5 build and ZIP structure checks;
- Mozilla `web-ext lint` with zero errors and zero warnings;
- a Firefox smoke test covering local icons, an unknown-domain letter, consent grant, consent denial, consent revocation, offline fallback, and a new-tab reload;
- checks for `sheets.google.com`, `docs.google.com/spreadsheets`, Reddit, GitHub, Vercel, Railway, Namecheap, ChatGPT, Claude, and an unknown domain;
- confirmation that the Chrome archive checksum remains unchanged.

## Store disclosure

The Firefox Add-ons listing and privacy disclosure state in plain Russian and English that popular icons are bundled locally, loading missing icons is optional and off by default, and enabling it sends only site domains to retrieve icons. The disclosure names the external hostname favicon provider used by the release and explains how to turn the feature off.

## Out of scope

- Any change to the Chrome extension or Chrome archive.
- Reading open tabs, history, page content, cookies, or browser bookmarks.
- `<all_urls>`, broad host permissions, OAuth, a backend, analytics, or advertising.
- Persisting or synchronizing favicon images, favicon URLs, or consent state.
- Scraping page HTML or manifests to discover icons.
- User-uploaded custom favicon images or a favicon cache.
- Changes to storage architecture, import/export format, backgrounds, folders, site editing, or layout.
